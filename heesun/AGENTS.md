# heesun 작업 규칙

heesun은 기획·마케팅 담당이다. 이 폴더(`heesun/`)에 기획 노트, 아이디어 메모, 레퍼런스 이미지 등을 자유롭게 올린다.
heesun은 git·GitHub을 모른다. **저장과 업로드는 전부 AI가 대신 하고, heesun은 대화만 한다.**

## 1. 말투: 개발 용어는 절대 쓰지 않는다

heesun에게 하는 말에는 개발과 조금이라도 관련된 용어를 쓰지 않는다. 꼭 필요하면 개발을 전혀 모르는 사람이 한 번에 알아듣게 일상 말로 풀어서 말한다. 애매하면 푼다.

| 쓰지 않는 말 | 대신 이렇게 |
| --- | --- |
| 커밋 / 푸시 / 풀·fetch / 머지 | 저장 / 올리기 / 최신 내용 받기 / 합치기 |
| 브랜치 | 오늘 작업 공간 |
| 충돌 | 같은 곳을 두 사람이 고쳐서 겹쳤어요 |
| 저장소·레포·GitHub·원격 | 함께 쓰는 보관함 |
| 마크다운, `#`·`**`·`-` 같은 기호 | "큰 제목, 작은 제목, 점 찍은 목록, 굵은 글씨로 정리한 메모" |
| 확장자(.md, .png, .pdf), 파일 경로(`heesun/notes/...`) | "메모 파일", "사진 파일", "기획 노트 폴더 안에" |
| 훅, 규칙 문서, AGENTS.md, 설정 | 말하지 않는다. 꼭 필요하면 "제가 지켜야 하는 약속" |
| 터미널, 명령어, 코드, 스크립트, 로그 | 말하지 않는다. AI가 조용히 직접 한다 |
| 오류 메시지 원문 | 무슨 일인지 쉬운 말로 한 줄 |
| HTML·CSS, 프로토타입·시제품, 배포 | "웹사이트 시안", "웹사이트에 올리기" |

- 위 표는 예시다. 표에 없어도 개발자 냄새가 나는 말(영어 약어, 기술 이름, 파일 형식 이름 등)은 모두 같은 원칙으로 푼다.
- 저장 메시지, 작업 공간 이름, 파일 내용 원문 같은 기계적인 것은 보여 주지 않는다. 파일 이름은 heesun이 물을 때만 알려 준다.
- 답은 평범한 문장과 간단한 목록으로 쓴다. 코드 상자나 회색 글씨 표시(백틱)는 쓰지 않는다.
- 쉬운 말로 짧게 말한다. heesun에게 무엇을 입력하거나 실행하라고 시키지 않는다.
- 아이디어를 판단하거나 고치려 들지 않는다. 정리를 부탁받았을 때만 정리한다.

## 2. 작업 범위

- 읽기: 저장소 전체를 읽어도 된다(예: 웹사이트 시제품, 공부 노트를 참고할 때).
- 쓰기: **`heesun/` 폴더 안만** 만들고 고치고 옮긴다. 밖의 파일은 바꾸지 않는다. 바꿀 일이 생기면 "개발 담당자에게 전달할게요"라고 말하고 `heesun/to-dev.md`에 요청을 적는다. 개발 담당자의 답은 `heesun/dev-response.md`에 온다(7절).
- 지우기·덮어쓰기: 하기 전에 무엇이 사라지는지 보여 주고 heesun의 확인을 받는다.

## 3. 파일 정리

- heesun이 올린 파일은 그대로 둔다. 이름과 위치를 바꾸는 것은 heesun이 원할 때만 한다.
- 새로 만드는 파일 이름은 `날짜-주제` 형식을 쓴다. 예: `2026-10-19-landing-copy-ideas.md`. 한글 제목도 괜찮지만 띄어쓰기 대신 `-`를 쓴다.
- 폴더 구조를 처음 정할 때는 heesun과 상의한다. 제안 예: `notes/`(기획 노트), `ideas/`(아이디어 메모), `refs/`(레퍼런스 이미지·링크).
- `docs/documentation-rules.md`의 문서 규칙(150줄 제한 등)은 이 폴더에 적용하지 않는다.
- 큰 파일: 한 파일이 50MB를 넘으면 올리지 않고, 줄이거나 링크로 남기자고 제안한다(GitHub 한도는 100MB).

## 4. 작업 공간: 반드시 `heesun/<날짜-주제>` 브랜치

heesun이 맞다고 하면 **파일을 만들거나 고치기 전에** 전용 브랜치부터 만든다. 훅이 브랜치 없이 `heesun/` 안을 고치는 것을 막는다.

0. 브랜치 이름의 주제는 heesun이 말한 할 일에서 정한다. 세션 첫 질문에 할 일까지 답했으면 그것을 쓰고, "네"만 했으면 짧게 **"어떤 작업을 해볼까요?"**라고 묻고(이 문구 그대로) 답을 듣기 전에는 다른 일을 하지 않는다(UserPromptSubmit·Stop 훅이 강제한다).
1. 최신 내용을 받는다: `git fetch origin` (`origin/HEAD`가 없다고 나오면 `git remote set-head origin -a`를 먼저 한 번 실행)
2. 아직 개발 담당자가 합치지 않은 heesun 브랜치가 있는지 본다: `git branch -r --list 'origin/heesun/*' --no-merged origin/HEAD`
   - 있으면 가장 최근 것을 바탕으로 한다(지난 작업이 이어져야 하므로).
   - 없으면 저장소 기본 브랜치(`origin/HEAD`)를 바탕으로 한다.
3. 새 브랜치를 만든다: `git switch -c heesun/<YYYY-MM-DD>-<짧은-영문-주제> <바탕>` 예: `heesun/2026-10-19-landing-copy`. 이름이 이미 있으면 끝에 `-2`, `-3`을 붙인다.
4. heesun에게는 "오늘 작업 공간을 만들었어요" 한 줄만 말한다.

## 5. 저장(커밋)과 업로드(푸시): 훅이 강제한다

- **작업 하나 끝날 때마다 바로 커밋한다.** `git add heesun/` 후 한국어 한 줄 메시지. 예: `heesun: 랜딩 문구 아이디어 메모 추가`. 커밋하지 않은 변경이 남은 채로는 턴을 끝낼 수 없다(Stop 훅).
- **저장했지만 아직 올리지 않은 작업이 있고, 이번 턴에 할 일을 마쳤으면** 답의 맨 끝에 아주 짧게 "오늘 작업 끝났나요?"라고 묻는다. 정확히 이 문구를 쓴다. 이 질문 없이는 턴을 끝낼 수 없다(Stop 훅).
- **묻지 않는 때:** 아직 아무것도 저장하지 않았을 때, heesun에게 내용이나 확인을 물어보고 답을 기다릴 때(답이 그 질문으로 끝나면 Stop 훅도 통과시킨다). 질문 두 개를 한꺼번에 하지 않는다.
- **끝났다고 하면 바로 올린다:** `git push -u origin <현재 브랜치>`. 그리고 "오늘 작업을 올렸어요. 개발 담당자가 확인한 뒤 합쳐요." 한 줄로 알린다.
- 끝나지 않았다고 하면 올리지 않고 계속한다.
- **금지:** 강제 업로드(`--force`), 기록 고쳐 쓰기(`rebase -i`, `reset --hard`, `commit --amend`), `heesun/` 밖 파일 담기, 기본 브랜치에 직접 커밋·업로드.

## 6. 문제가 생기면

- **업로드가 거절됨:** 같은 브랜치를 다른 곳에서 올린 경우다. `git pull --rebase` 후 다시 올린다. heesun에게는 "최신 내용을 받아서 다시 올렸어요"라고만 말한다.
- **같은 파일을 둘이 고쳐 겹침:** heesun의 파일이면 두 내용을 다 살려 합치고 heesun에게 보여 준다. `heesun/` 밖 파일이면 손대지 않고 진행을 멈춘 뒤, "개발 담당자에게 확인이 필요해요"라고 말한다.
- **로그인·권한 오류:** heesun에게 쉬운 말로 상황을 설명하고 개발 담당자에게 연락하라고 안내한다. 비밀번호나 토큰을 대화에 붙여 넣으라고 하지 않는다.
- 어떤 경우에도 heesun의 파일이 사라지면 안 된다. 확신이 없으면 멈추고 묻는다.

## 7. 세션을 시작할 때

0. 세션 첫 답에 훅이 "새 답변"을 알리면, 다른 일보다 먼저 `heesun/dev-response.md`의 해당 행을 읽고 "질문에 대한 답이 왔어요"라며 질문과 답을 쉬운 말로 전한다. 작업 공간을 만든 뒤 그 행의 상태를 "전달 완료"로 바꿔 저장한다(바탕에 파일이 없으면 기본 브랜치의 것을 가져와 만든다).
1. 할 일을 아직 안 들었으면 "어떤 작업을 해볼까요?"라고 묻는다.
2. 그 할 일로 4절대로 작업 브랜치를 만든다.
3. (처음이면) 이 폴더에 무엇이 있는지 보여 주고 폴더 정리 방식을 상의한다(위 3절 제안).
4. 말한 작업을 시작한다.

## 8. 훅 (`.claude/settings.json`)

| 훅 | 하는 일 |
| --- | --- |
| SessionStart | 모든 세션 시작에 "heesun 님이신가요? 맞다면 오늘 어떤 작업을 할지도 같이 알려 주세요."를 먼저 묻게 한다 |
| UserPromptSubmit (`heesun-prompt.sh`) | 세션 첫 답이 신원 질문일 때만 작동(설명 속 같은 문구로 오작동하지 않게 처음 두 답만 본다). 첫 질문의 답이면 할 일이 있으면 브랜치부터, 없으면 "어떤 작업을 해볼까요?"만 묻게, 그 질문의 답이면 답으로 브랜치를 만들게 안내한다. 개발자라고 답하면 원격 최신 내용을 받고(현재 브랜치는 fast-forward), 기본 브랜치가 앞서 있는지와 현재 브랜치에 없는 heesun 브랜치를 알리고 합쳐 내용을 보여 주게 한다(`heesun/*` 브랜치에서는 작동 안 함). heesun 세션 첫 답이면 `dev-response.md`에 아직 전달 안 된 "새 답변"이 있는지 보고 있으면 먼저 전하게 안내한다 |
| PreToolUse (`heesun-guard.sh`) | `heesun/*` 브랜치에서는 `heesun/` 밖 쓰기를, 다른 브랜치에서는 `heesun/` 안 쓰기를 막는다(이 규칙 문서와 개발 담당자의 답변 파일 `dev-response.md`는 예외) |
| Stop (`heesun-stop.sh`) | 다른 브랜치에서는 세션 첫 질문에 아니라고(아니·아뇨·개발…) 하지 않았는데 그 턴에 브랜치도 안 만들고 "어떤 작업을 해볼까요?"도 안 물은 경우와, 개발자라고 했는데 그 턴에 기본 브랜치·현재 브랜치의 원격·`origin/heesun/*` 브랜치를 합치지 않은 경우, `heesun/*` 브랜치에서는 ① 밖 변경 ② 커밋 안 한 변경 ③ 올리지 않은 저장분이 있는데 "오늘 작업 끝났나요?"도, 다른 질문도 없이 끝내는 경우 턴 종료를 막는다 |
