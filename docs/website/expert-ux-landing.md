# 전문가 의견: 랜딩 페이지와 계정 (UX/UI 디자이너)

> 2026-10-12 · [expert-ux-review.md](expert-ux-review.md)와 같은 페르소나 · 사용자의 "책이 펼쳐지는 랜딩" 아이디어를 구체화

## 결론

책은 장식이 아니라 **사이트로 들어가는 문**이다. 책이 열리면 펼친 양면이 그대로 화면이 되고, 양면에 그려진 시대 띠가 곧 방 목록이 된다. 디자인은 **실사 3D가 아니라 절제된 반(半)실물**로 간다. 근거리 사진 같은 질감, 조명 하나, 4초 이내. 촌스러움은 책이 아니라 장식(가죽, 금박, 책상, 먼지, 페이지 말림)에서 나온다.

## 1. 스토리보드 (데스크톱, 처음 방문)

| 시간 | 화면 | 결정 |
| --- | --- | --- |
| 0.0s | 따뜻한 차콜(#1a1816) 배경 가운데 닫힌 책. 화면 높이 40%. 이미 조명을 받고 있다 | 첫 프레임이 이미 완성된 장면이다. 스피너나 빈 화면은 없다 |
| 0.0–1.0s | 좌상단 낮은 조명이 밝아지며 표지의 천 결이 드러난다 | 무광 클로스 한 색(짙은 먹청 또는 바랜 테라코타). 금박·가죽·엠보싱은 쓰지 않는다 |
| 표지 | 「서양 미술사」는 한글 명조, 아래에 작은 이탤릭 세리프로 *The Story of Art* | 원서 표지를 흉내 내지 않는다(트레이드 드레스 문제). 작은 글씨로 "곰브리치를 따라 걷는 미술사" |
| 1.2–2.0s | 표지가 왼쪽 경첩으로 열리면서(700ms, 감속) **동시에** 카메라가 다가간다 | 두 동작을 겹친다. 따로 하면 PPT 같다 |
| 2.0–2.4s | 속장 몇 장이 빠르게 넘어간다 | 페이지 말림 효과는 쓰지 않는다. 평평한 회전과 그림자만 |
| 2.4–3.4s | 펼친 양면이 화면을 채우고 종이색이 사이트 배경이 된다. 잉크 선이 그어지며(연표) 시대 이름이 조판되고, **작품 세부 도판**(헤지레의 눈, 카라바조의 손가락)이 인쇄되듯 나타난다 | 클라이맥스. 작품 전체보다 세부가 궁금증을 만든다 |
| 3.4s~ | 정지. 마우스를 올리면 도판이 커지고 그 시대의 방들이 펼쳐진다 | 대기 중에는 아무것도 움직이지 않는다 |
| 방 입장 | 누른 세부가 **그대로 확대되어** 방의 첫 화면이 된다(600ms). 뒤로 가기는 역재생 | 책장 넘김은 랜딩에서 한 번만 쓴다 |

전체 4초 이하. 튕기는 이징, 소리, 배경음악은 쓰지 않는다. 서체는 한글 명조 1종과 본문 산세리프 1종.
**함정:** 서재 배경, 먼지 파티클, 세피아, 타자기 효과, 클래식 배경음, 무거운 WebGL 책, "클릭해서 책을 여세요" 대기 화면.

## 2. 타임라인 = 방 목록

- **형태:** 펼친 양면 위의 가로 시대 띠. 시간을 비례로 잡지 않고 칸 폭을 같게 한다. 왼쪽 면은 고대~중세, 오른쪽 면은 르네상스~현대로, 책등이 구분선이 된다. 서문은 "들어가며" 쪽에 둔다.
- **추천: 랜딩에는 8개 시대, 그 안에 18개 방.** 시대 칸을 누르면 방 2–4개가 펼쳐진다. 18칸을 한꺼번에 펼치면 목차처럼 무겁다.
- 8개 시대: 원시 / 이집트·메소포타미아 / 그리스·로마 / 중세 / 르네상스(15·16세기·매너리즘) / 바로크·로코코 / 19세기 / 20세기 이후

## 3. 재방문자

- 애니메이션을 다시 보여 주지 않는다. 책이 **이미 펼쳐진 채 읽던 시대에 책갈피 리본이 꽂힌 상태**로 0.6초 만에 자리 잡는다. 첫 장면은 하단의 작은 링크로 다시 볼 수 있다.
- 다 본 방은 칸이 잉크로 채운 듯 진해지고, 보던 방은 아래에 얇은 진행선이 생긴다. 숫자, 퍼센트, 배지는 쓰지 않는다.
- 앞에 버튼 하나: **"이어서 보기: 바로크 · 세 가지 빛"**.
- 클릭, 스크롤, 아무 키나 누르면 즉시 마지막 상태로 건너뛴다.

## 4. 이메일 없는 계정

| 방식 | 장점 | 문제 |
| --- | --- | --- |
| 브라우저 저장만 | 마찰이 없다 | Safari는 7일간 방문이 없으면 스크립트가 저장한 데이터를 지운다. 기기 간 이동 불가 |
| 닉네임 + PIN | 익숙하다 | 대입 공격에 약하고, 잊으면 복구할 수 없다 |
| 패스키 (지문·얼굴) | 입력이 없고 안전하다. iCloud·Google로 기기 간 동기화 | 아직 생소한 개념 |
| 복구 코드 | 혼자서도 쓸 수 있다 | 보관이 번거롭다. 보조 수단으로만 |

**추천: 익명 자동 기록(서버 저장 + 서버가 설정하는 HttpOnly 쿠키) → 원하는 사람만 패스키로 "내 서재 만들기" → 복구 코드로 백업.**
- 가입 권유는 **첫 방을 다 본 직후 한 번만** 한다. 랜딩에서 바로 묻지 않는다.
- 체크 단위는 **정거장**(방마다 5–8개)이다. 충분히 머문 장면을 자동 체크한다.
- 랜딩에서는 서문을 읽은 것만 체크하고, 미리 보기는 체크하지 않는다.

## 5. 모바일

- 책은 한 면짜리 세로 판형이다. 표지가 열리면 오른쪽 면이 화면을 채운다.
- 시대 띠는 세로 연표가 되고, 칸을 탭하면 아코디언으로 방이 펼쳐진다.
- 책갈피는 오른쪽 가장자리에 두고, "이어서 보기"는 하단에 고정한다. 시퀀스는 3초 이하로 줄인다.

## 6. 접근성과 성능

- 방 목록은 처음부터 실제 HTML 목록(`nav > ol`)으로 존재하고, 애니메이션은 그 위의 연출일 뿐이다.
- `prefers-reduced-motion`이면 200ms 디졸브만 쓴다. 포커스와 스크롤을 막지 않는다. 글자 대비는 4.5:1 이상.
- 책은 CSS 3D와 텍스처 1장(100KB 이하)으로 만든다. 첫 화면은 300KB 이하. 고해상도 이미지는 방에 들어갈 때 받는다.

## 사용자에게 확인할 것

1. 표지 색과 판형 (시안 2–3개로 비교)
2. 8개 시대로 묶는 방식
3. 진도를 서버에 저장하는 것 (익명이어도 개인정보 처리방침이 필요하다)
4. 계정 기능의 범위 (즐겨찾기, 메모 등)
